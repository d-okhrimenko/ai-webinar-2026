# Архітектура проєкту

Проєкт складається з Angular-клієнта та ASP.NET Core Web API.

## Структура

```text
client/                         Angular 22 застосунок
api/ReviewsAssistant/           серверна частина .NET
  ReviewsAssistant.slnx         solution серверних проєктів
  ReviewsAssistant.Core/        ядро бізнес-моделі
  ReviewsAssistant.Application/ сценарії застосунку та контракти
  ReviewsAssistant.Infrastructure/ технічні реалізації
  ReviewsAssistant.WebAPI/      HTTP API та точка запуску
context/                        документація проєкту й поточних задач
```

## Серверна частина

Сервер використовує .NET 10 та поділений на чотири проєкти:

- `Core` — сутності, переліки та бізнес-правила. Не залежить від інших проєктів.
- `Application` — сценарії роботи, DTO та інтерфейси для доступу до зовнішніх залежностей. Залежить від `Core`.
- `Infrastructure` — реалізації доступу до даних і зовнішніх сервісів. Залежить від `Application` та `Core`.
- `WebAPI` — контролери, HTTP-конфігурація та реєстрація залежностей. Залежить від `Application` і `Infrastructure`.

Напрямок залежностей:

```text
Application    → Core
Infrastructure → Application, Core
WebAPI         → Application, Infrastructure
```

Контролери мають лише приймати HTTP-запит, викликати сценарій з `Application` і повертати HTTP-відповідь. Вони не працюють напряму з базою даних або конкретними реалізаціями `Infrastructure`.

Запуск API: `dotnet run` з каталогу `api/ReviewsAssistant/ReviewsAssistant.WebAPI`.

## Клієнтська частина

Клієнт розташований у `client/` і створений на Angular 22 зі standalone-компонентами. Маршрути, компоненти та сервіси розміщуються у `client/src/app/`. Для змін клієнта дотримуйся правил у `client/AGENTS.md`.

Запуск клієнта: `ng serve` з каталогу `client/`.

## Поточний стан

У серверній частині наразі є стандартний приклад `WeatherForecast`; бізнес-функції, база даних, автентифікація та AI-інтеграція ще не реалізовані. У клієнті поки використовується стартовий шаблон Angular без прикладних маршрутів.

## Правила розвитку

- Нові бізнес-сутності та правила додавай у `Core`.
- Сценарії, DTO й інтерфейси залежностей додавай у `Application`.
- Роботу з БД, зовнішніми API та інші технічні деталі реалізуй в `Infrastructure`.
- Не створюй зворотних або циклічних залежностей між серверними проєктами.
- API не повинно повертати доменні сутності напряму: використовуй DTO.
- Секрети та ключі зовнішніх сервісів не зберігай у репозиторії й не передавай у клієнт.
