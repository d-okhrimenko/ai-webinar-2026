# Контекст проєкту: Reviews Assistant

Потрібно створити демонстраційний full-stack застосунок для вебінару про підключення OpenAI API до .NET-бекенду.

## Мета

Показати реалістичний бізнес-сценарій: користувач залишає відгук про сервіс, а система за допомогою AI аналізує його тональність, категорію та терміновість. Адміністратор бачить пріоритизовані відгуки й може згенерувати чернетку відповіді клієнту.

До вебінару потрібно підготувати весь застосунок, окрім реальної інтеграції з OpenAI. Під час вебінару AI-частина додаватиметься поетапно у форматі live coding.

## Технології

- Backend: ASP.NET Core Web API, актуальна стабільна версія .NET.
- Frontend: Angular, standalone components.
- База даних: PostgreSQL.
- ORM: Entity Framework Core, migrations.
- Авторизація: проста JWT-авторизація лише для адміністратора.
- Взаємодія клієнта з API: HTTP API.
- UI: мінімалістичний і охайний, сучасний, без складної дизайн-системи.

## Ролі та доступ

У застосунку є дві зони:

1. Публічна сторінка зворотного зв’язку — доступна без авторизації.
2. Адмін-панель — доступна лише авторизованому адміністратору.

Не потрібно реалізовувати реєстрацію, підтвердження email, відновлення пароля або складну рольову модель. Достатньо одного наперед створеного адміністратора, входу та JWT-токена.

## Сценарій користувача

На публічній сторінці користувач заповнює форму:

- ім’я;
- email;
- текст відгуку.

Після відправлення відгук зберігається в базі даних, а користувач бачить повідомлення про успішне надсилання.

## Сценарій адміністратора

Адміністратор входить у систему та бачить список усіх відгуків.

Для кожного відгуку відображаються:

- ім’я автора;
- email;
- текст;
- дата створення;
- статус аналізу;
- тональність;
- пріоритет;
- категорія;
- короткий підсумок;
- ознака необхідності термінової реакції.

Адміністратор може відкрити картку відгуку та переглянути деталі. У картці має бути блок «Чернетка відповіді клієнту» і кнопка «Згенерувати відповідь». До підключення AI кнопка може бути неактивною або показувати зрозумілу заглушку: «AI-інтеграцію буде підключено пізніше».

## Модель даних

### Review

- `Id` — GUID.
- `AuthorName` — обов’язкове ім’я автора.
- `Email` — обов’язковий email.
- `Text` — обов’язковий текст відгуку.
- `CreatedAtUtc` — дата створення.
- `AnalysisStatus` — `Pending`, `Processing`, `Completed`, `Failed`.
- `Sentiment` — nullable: `Positive`, `Neutral`, `Negative`.
- `Priority` — nullable: `Low`, `Medium`, `High`, `Critical`.
- `Category` — nullable: наприклад `Praise`, `FeatureRequest`, `Bug`, `PaymentIssue`, `Support`, `Other`.
- `NeedsUrgentResponse` — nullable boolean.
- `Summary` — nullable рядок.
- `AiDraftResponse` — nullable рядок.
- `AnalyzedAtUtc` — nullable дата аналізу.

На підготовчому етапі AI-поля можуть бути порожніми, а статус аналізу — `Pending`.

## API

Публічні endpoints:

- `POST /api/reviews` — створити відгук.
- `GET /api/reviews/{id}/submission-status` — за потреби отримати статус відправлення.

Авторизовані admin endpoints:

- `POST /api/auth/login` — вхід адміністратора.
- `GET /api/admin/reviews` — список відгуків із фільтрами та сортуванням.
- `GET /api/admin/reviews/{id}` — детальна картка відгуку.
- `POST /api/admin/reviews/{id}/analyze` — endpoint створити заздалегідь, але до вебінару повертати заглушку.
- `POST /api/admin/reviews/{id}/draft-response` — endpoint створити заздалегідь, але до вебінару повертати заглушку.

## Angular-сторінки

- `/feedback` — публічна форма відгуку.
- `/login` — форма входу адміністратора.
- `/admin/reviews` — таблиця або список відгуків.
- `/admin/reviews/:id` — детальна картка відгуку.

Додати:

- auth interceptor для додавання JWT;
- guard для `/admin`;
- стани завантаження та помилок;
- фільтри за статусом, тональністю та пріоритетом;
- сортування за датою й пріоритетом;
- візуальні мітки пріоритету та тональності.



## Що буде реалізовано на вебінарі

Під час live coding потрібно:

1. Додати конфігурацію OpenAI API через environment variables або User Secrets.
2. Створити сервіс `AiReviewAnalyzer`.
3. Передати текст відгуку до моделі.
4. Отримати суворо структурований результат:
   - `sentiment`;
   - `priority`;
   - `category`;
   - `needsUrgentResponse`;
   - `summary`.
5. Провалідувати та зберегти результат у PostgreSQL.
6. Відобразити результат в адмін-панелі.
7. Створити `AiResponseGenerator`, який формує ввічливу чернетку відповіді клієнту.
8. Показати, що чернетка створюється для адміністратора, але не надсилається автоматично.

## Вимоги до AI-частини

AI-інтеграція має виконуватися лише на сервері. Ніколи не передавати API-ключ на Angular-клієнт і не зберігати його в репозиторії.

Використати окремі сервіси та інтерфейси:

- `IAiReviewAnalyzer`;
- `IAiResponseGenerator`.

Код має бути зрозумілим для демонстрації: мінімум абстракцій, ясні DTO, обробка помилок, `CancellationToken`, обмеження довжини вхідного тексту та логування без витоку персональних даних.

Не будувати для MVP складного автономного агента, tool calling, черги повідомлень або фонові воркери. Наприкінці вебінару можна обговорити їх як можливі напрями розвитку production-версії.
