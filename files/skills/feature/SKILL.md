# Feature Workflow

Завдання навички — керувати процесом реалізації фічі від постановки задачі до злиття гілки та публікації результату.

## Робочий файл

`context/current-feature.md` містить опис поточної фічі. Шляхи `context/…` відраховуються від кореня репозиторію.

### Структура файла current-feature.md

- H1 — назва активної фічі або `# Current Feature`, коли активної фічі немає.
- `## Цілі` — маркований список критеріїв приймання фічі.
- `## Нотатки` — додатковий контекст, правила або деталі.
- `## Історія` — список реалізованих фіч. Нові записи додаються, а попередні не редагуються.

Фіча активна, якщо H1 містить її назву замість `Current Feature`, а розділ `## Цілі` містить критерії приймання. Початковий стан — H1 `# Current Feature` та порожні цілі й нотатки; історія може містити записи. Якщо файл відсутній або не містить активної фічі, запропонуй виконати `load` перед `start`, `review` чи `complete` і не виконуй ці дії.

## Можливі дії

Перше слово `$ARGUMENTS` — команда, решта тексту — її аргументи. Передай у файл дії лише аргументи без назви команди.

| Дія | Опис |
|-----|------|
| [`load`](actions/load.md) | Завантажити вимоги з файла або тексту в `context/current-feature.md` |
| [`start`](actions/start.md) | Почати реалізацію активної фічі в окремій гілці |
| [`review`](actions/review.md) | Перевірити реалізацію фічі та сформувати звіт |
| [`complete`](actions/complete.md) | Закомітити зміни фічі, злити гілку в цільову, оновити історію, виконати push і видалити гілку фічі локально та з `origin`; якщо проєкт вимагає PR, підготувати завершення через PR |

Читай лише файл вибраної дії. Приклади викликів:

- `$feature load login` — завантажити `context/features/login.md`.
- `$feature load Додати відновлення пароля` — сформувати вимоги з текстового опису.
- `$feature start` — почати реалізацію активної фічі.
- `$feature review` — перевірити результат.
- `$feature complete` — завершити роботу та опублікувати результат.

Якщо команду не задано або вона невідома, поясни доступні дії. Команди `start`, `review` і `complete` не потребують аргументів.

Не запитуй повторного погодження звичайних кроків, уже дозволених користувачем. Уточнення потрібні перед перезаписуванням активної фічі, за наявності неоднозначних змін або якщо спосіб публікації не визначений.
