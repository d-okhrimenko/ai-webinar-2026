# Load Action

1. Перевір аргументи після команди `load`:
   - Якщо це назва файла, прочитай `context/features/{name}.md`; не додавай розширення повторно, якщо `.md` вже вказано. Назву з пробілами користувач може взяти в лапки.
   - Якщо це текстовий опис функціональності, використай його для оформлення `context/current-feature.md`.
   - Якщо файл не знайдено або незрозуміло, чи передано назву файла, чи опис, попроси уточнення. Не перетворюй відсутню назву файла на вимоги автоматично.
   - Якщо аргументів немає, попроси вказати назву файла або пояснити, що потрібно реалізувати.

2. Онови `context/current-feature.md` або створи його, якщо він відсутній:
   - Перед заміною активної фічі отримай погодження, якщо користувач ще не дозволив її перезаписати.
   - У H1 вкажи назву фічі, яка буде реалізовуватися.
   - У розділі `## Цілі` опиши перевірювані критерії приймання маркованим списком.
   - У розділі `## Нотатки` вкажи додаткові вимоги та деталі.
   - Збережи розділ `## Історія` та всі попередні записи; у новому файлі залиш його порожнім.

3. Підтвердь, що файл оновлено, та надай короткий підсумок.
